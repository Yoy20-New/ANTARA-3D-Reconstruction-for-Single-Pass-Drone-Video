# ANTARA Pipeline — Progress & Changelog (Sept 27-28, 2026)

## 1. History & Implementations

Over the course of the recent sessions, several critical pipeline and visualization issues were identified and resolved. 

### A. FBX Export Failure
* **Problem:** The pipeline was failing to export `.fbx` models because the `pyassimp` dependency was either missing or unable to bind to the assimp binaries.
* **Solution:** Cleaned up the conda environment, installed `assimp` explicitly via `conda-forge`, and rewrote the `export_fbx` function in `antara/deliverables.py` to robustly handle the pyassimp scene export.

### B. Metric Spatial Accuracy & Distortion (Georeferencing)
* **Problem:** The pipeline was failing spatial accuracy checks (ATE > 3m). The point cloud was exhibiting non-linear warping, and narrow-corridor drone flights caused the PCA logic to induce massive "roll" errors, tilting the ground plane.
* **Solution:** 
  * Locked the 3D similarity transform scale to exactly `1.0` (Rigid body only) to prevent RANSAC from shrinking/expanding the model.
  * Added fallback logic in `georeference.py` to prevent extreme roll in linear flight corridors.
  * Disabled the 1D Thin Plate Spline (TPS) Z-warping, which was heavily distorting the final 3D structure.

### C. Web Viewer Point Size Bug
* **Problem:** The point size slider in `index.html` wasn't working. WebGL was clamping the world-unit sizes to 1 pixel because `sizeAttenuation` was forced on.
* **Solution:** Built a dual-mode point size system. Users can now seamlessly toggle between **Screen Mode (px)** (crisp, constant size regardless of zoom) and **World Mode (m)** (perspective scaling). Added memory variables so the slider doesn't reset when switching modes.

### D. UI/UX Minimalist Overhaul
* **Problem:** The 3D viewer UI was cluttered with unnecessary telemetry, broken lighting sliders, and clashing colors.
* **Solution:** Completely rewrote the `index.html` UI from scratch:
  * Implemented a clean, monochrome aesthetic using responsive `clamp()` font sizes.
  * Removed unnecessary status pills ("ONLINE") and unlit-material lighting sliders.
  * Consolidated all controls (FOV, Point Size, Opacity, Grid Color, Background Color) into a neat slide-out Settings Panel with live updates.
  * Added the Antara brand logo dynamically to the top right.

### E. Mesh Misalignment & "Sky Bowl" Artifacts
* **Problem:** The OBJ mesh was rotated 90 degrees sticking straight up into the air, completely misaligned from the point cloud. Furthermore, the edges of the mesh swept up into a massive, ugly grey "bowl".
* **Solution:** 
  * **Alignment Fix:** The PLY was correctly undergoing an ENU → Three.js coordinate transform (`X, Y, -Z` and centering), but the OBJ was bypassing it. Wrote `alignObjMesh()` in JavaScript to apply the exact same geographic offsets and rotation to the OBJ vertices upon loading.
  * **Trimming Fix:** The "bowl" was an artifact of Poisson surface reconstruction extrapolating into empty space. Updated `antara/deliverables.py` to extract the Poisson density values and automatically trim the bottom 5% of lowest-density triangles, resulting in a crisp, clean mesh that hugs the ground.

## 2. Next Implementation Plan: Client-Side Drag & Drop Upload

**Objective:** Upgrade `index.html` to allow end-users to drag and drop their own `.ply` or `.obj` files directly into the browser to view them instantly, complete with a detailed progress/status tracker.

### Step-by-Step Implementation Guide

**Step 1: HTML & CSS Additions (Dropzone & Status UI)**
* Add a full-screen `<div id="dropzone">` overlay that remains hidden until the user drags a file over the browser window.
* Update the `loader` UI to serve as a detailed status tracker, with a text field that can update through phases: "Reading File", "Parsing PLY", "Computing Bounding Box", "Generating Heatmap", etc.

**Step 2: JavaScript File API (Drag & Drop Handlers)**
* Bind `dragover`, `dragenter`, and `dragleave` events to the `window` to show/hide the dropzone overlay.
* Bind the `drop` event to intercept the file, prevent default browser behavior (which would normally just download the file), and pass it to a `FileReader`.

**Step 3: Refactoring Three.js Loaders for ArrayBuffers**
* Currently, `PLYLoader.load(url)` fetches from a hardcoded path. We will change this to read the dropped file as an `ArrayBuffer` using `FileReader.readAsArrayBuffer(file)`.
* Once the buffer is read, we pass it to `PLYLoader.parse(buffer)` to generate the Three.js geometry directly in memory.

**Step 4: Memory Management (Cleanup Routine)**
* Before loading a new dropped file, we must safely remove the existing `pointCloud` or `objMesh` from the scene.
* Write a `disposeModel()` function that calls `geometry.dispose()` and `material.dispose()` to prevent memory leaks if a user drops 10 different models in a single session.

**Step 5: Status & Progress Reporting**
* Since parsing a 100MB+ PLY blocks the main JavaScript thread, we will use `setTimeout` yields to update the DOM status text *before* heavy operations.
* **Flow:** 
  1. `Status: Reading file from disk...` (FileReader active)
  2. `Status: Parsing PLY geometry...` (Three.js parse active)
  3. `Status: Computing geographic bounds...` (ENU logic)
  4. `Status: Generating elevation heatmap...` (Turbo colormap logic)
  5. `Status: Rendering...` (Final scene add)
